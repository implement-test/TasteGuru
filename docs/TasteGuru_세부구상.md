# TasteGuru 세부 구상 (2026-10-11)

> 기획 명세(`TasteGuru.md`)를 검토해 개발 시작 전에 정할 것들을 정리한 문서입니다. 아직 코드는 없습니다.

## 1. 개발 전 확인 필요 분석

### 1-1. 쿠팡, 컬리 등 온라인 마켓에서 정보 가져오기 → **일부 가능**

| 출처 | 방법 | 결과 | 가져올 수 있는 정보 | 비고 |
| --- | --- | --- | --- | --- |
| 네이버 쇼핑 | 공식 **검색 API** (`/v1/search/shop.json`) | **가능** | 제품명, 대표 이미지, 최저가·최고가, 판매처, 브랜드·제조사, 카테고리 1~4 | 무료, 하루 25,000회. 키는 서버에만 둠. 네이버 쇼핑에 쿠팡·컬리 상품도 상당수 노출되므로 실질적으로 **가장 넓은 입력 경로** |
| 쿠팡 | 파트너스 **상품 검색 API** | 조건부 | 상품명, 이미지, 가격, 링크 | 파트너스 가입 후 **최종 승인(누적 판매 실적 조건, 블로그 기준 15만 원)** 이후에만 키 발급. 본인 구매로 실적 쌓기 금지. 개인 취미 프로젝트에는 현실성이 낮음 |
| 쿠팡 | 상품 페이지 직접 크롤링 | **불가에 가까움** | — | 서버 요청이 봇 차단(Access Denied)되는 사례 다수, 약관상 자동 수집 제한. 유지보수 부담 큼 |
| 컬리 | 공식 API | **없음** | — | 웹이 내부적으로 쓰는 비공식 경로만 존재 → 구조 변경 시 바로 깨짐. 로그인·배송지 기반 정보는 비로그인 조회 불가 |
| 공통 | 상품 URL의 **Open Graph 메타**(`og:title`, `og:image`) 읽기 | 일부 가능 | 제목, 대표 이미지 | 사이트별로 봇 차단·JS 렌더링 때문에 실패할 수 있음. 실패하면 직접 입력으로 자연스럽게 넘어가게 설계 |
| 공통 | 영양 정보 추출 | **불가** | — | 영양성분표는 대부분 **상세페이지 이미지 안**에 있어 텍스트로 가져올 수 없음 (이미지 판독은 AI 분석에 해당해 `하지 않을 것`과 충돌) |

**결론과 추천 입력 흐름**

1. **제품 검색(기본)**: 앱 안에서 제품명을 치면 네이버 쇼핑 검색 결과가 뜨고, 고르면 이름·이미지·브랜드·가격·카테고리가 자동 입력됨
2. **URL 붙여넣기(보조)**: 쿠팡·컬리 링크를 붙여넣으면 서버가 OG 메타 추출을 시도 → 실패 시 "직접 입력해 주세요" 안내
3. **직접 입력 + 사진 촬영/업로드**: 항상 가능한 마지막 경로. 모바일에서는 카메라 바로 열기

> ⚠️ 이 세션의 네트워크 정책상 쿠팡·컬리·네이버에 직접 접속 테스트를 하지 못했습니다. 위 판단은 공개 자료 기준이며, **개발 0단계에서 실제 호출 PoC로 재확인**합니다.

**이미지 저작권 메모**: 쇼핑몰 이미지는 판매자 저작물입니다. 10인 이하 비공개 그룹이라 위험은 낮지만, 기본은 **원본 이미지 URL만 저장(핫링크)** 하고, 사용자가 직접 찍은 사진만 우리 저장소에 올리는 방식을 추천합니다. 링크가 깨지면 기본 일러스트로 대체합니다.

### 1-2. (추가) 영양 정보 자동 입력 → **일부 가능**

- 식약처 **식품영양성분 DB(K-FIND, 2026-07 출범)** 를 공공데이터포털 Open API로 조회 가능 (가공식품 약 29.8만 건)
- 쇼핑몰 제품명 ≠ DB 제품명인 경우가 많아 자동 매칭은 불확실 → "영양 정보 찾기" 버튼으로 사용자가 직접 선택
- **MVP 이후**로 미루는 것을 추천 (명세의 핵심 목적은 맛 평가)

### 1-3. (추가) 무료 플랜으로 상시 운영 → **기타**

- Supabase 무료 플랜: DB 500MB, 파일 1GB, 월 전송 5GB → 10인 이하에 충분
- 단, **7일간 활동이 없으면 일시정지**(데이터 보존, 수동 복구). → 주 1회 자동 백업 작업이 DB 접속을 겸하게 해서 방지
- Vercel Hobby 플랜은 **비상업적 개인 용도**만 허용 → 이 프로젝트에 해당

## 2. 명세 검토 – 빠지거나 모호한 점 (답변 필요)

각 질문에 **제 기본 제안**을 달았습니다. 답이 없으면 기본 제안대로 진행합니다.

### 꼭 정해야 하는 것 (데이터 구조에 영향)

| # | 질문 | 기본 제안 |
| --- | --- | --- |
| Q1 | **맛 항목은 "강도"인가요, "선호"인가요?** 예: 맵다 5점 = "아주 맵다"인지 "매운 정도가 아주 좋다"인지. 강도라면 평균이 높다고 좋은 음식이 아닙니다 | **두 가지를 분리**: ① 맛 프로필(강도, 0~5, 선택 입력) ② **종합 만족도**(별 1~5) — "음식 점수"와 정렬 기준은 종합 만족도 평균 |
| Q2 | 맛 항목 목록은? 사용자가 항목을 추가할 수 있나요? | 기본 8개: 단맛·짠맛·매운맛·신맛·쓴맛·감칠맛·느끼함·식감(바삭/쫄깃은 메모로). **관리자만 항목 추가** (항목이 늘면 평균 비교가 흐트러짐) |
| Q3 | "음식"의 단위는? **특정 제품**(비비고 왕교자)인가요, **배달 가게 메뉴**(○○식당 김치찌개)도 포함인가요? | 둘 다 지원: 공통 필드 + `구매처/가게명` 필드. 네이버 검색 자동 입력은 제품에만 적용 |
| Q4 | 그룹은 하나(지인 전체)인가요, 여러 그룹이 따로 쓰나요? | **하나의 그룹**으로 시작 (10인 이하). 나중에 확장 가능하게 테이블만 준비 |
| Q5 | **가입 제한**: 인터넷 공개이므로 구글 계정만 있으면 누구나 들어올 수 있게 할까요? | **초대 링크 또는 허용 이메일 목록**으로 제한. 첫 가입자 = 관리자 |
| Q6 | "개인 메모"는 본인만 보나요, 그룹원에게 보이나요? | 메모는 **본인만**, 점수는 그룹 공개. (원하면 "공개 한줄평" 필드를 따로 추가) |
| Q7 | 같은 음식을 다시 먹었을 때 평가 이력을 남기나요? | MVP는 **1인 1평가, 수정 시 덮어쓰기** + 마지막 수정일 표시 |
| Q8 | 사진 5장은 **음식당 전체 5장**인가요, **사용자별 5장**인가요? | **음식당 전체 5장** (대표 이미지 1 + 추가 4) |

## 3. 기술 스택 추천

| 구분 | 추천 | 이유 |
| --- | --- | --- |
| 프레임워크 | **Next.js (App Router) + TypeScript** | 네이버 API 키 숨기기와 URL 메타 추출은 **서버**에서 해야 함(브라우저에서는 CORS로 막힘). Next.js는 화면과 서버 API를 한 프로젝트에서 처리. 채팅형 개발 도구로 다루기 쉬운, 자료가 가장 많은 스택 |
| DB | **Supabase (PostgreSQL)** | 평가·태그·묶음은 다대다 관계와 **평균 집계**가 핵심 → 관계형 DB가 적합. SQL 뷰로 평균을 실시간 계산 |
| 인증 | **Supabase Auth – Google 로그인** | 명세의 구글 인증을 설정만으로 지원. RLS(행 단위 권한)로 "메모는 본인만" 같은 규칙을 DB에서 강제 |
| 파일 저장 | **Supabase Storage** | 사진 업로드. 업로드 전 브라우저에서 리사이즈·압축(장당 ~300KB)해 1GB 무료 용량 안에서 수천 장 가능 |
| 호스팅 | **Vercel (Hobby, 무료)** | Next.js 제작사. Git 푸시 = 자동 배포, 미리보기 주소 제공 |
| UI | **shadcn/ui + Tailwind CSS** | 컴포넌트 코드를 프로젝트에 복사해 쓰는 방식이라 **파스텔·레트로 테마로 자유롭게 변형** 가능. Radix 기반이라 키보드·스크린리더 접근성 기본 제공. 다크 모드 내장 |
| 차트 | **Recharts** | 맛 프로필 레이더 차트, 묶음 비교 겹쳐 보기 |
| 백업 | **GitHub Actions (주 1회)** | 무료. DB를 JSON으로 내보내 비공개 저장소에 보관 + Supabase 일시정지 방지 |

**검토했지만 제외한 것**

- Firebase: NoSQL이라 "항목별 평균", "묶음-음식 다대다" 같은 집계·관계 처리가 번거로움
- 순수 정적 사이트(HTML+JS만): 서버가 없어 API 키를 숨길 수 없고 URL 메타 추출이 불가

## 4. 데이터 모델 (초안)

```
profiles          사용자 (id=구글 계정, 닉네임, 아바타, role: admin|member)
invites           초대 (code 또는 email, 사용 여부)

foods             음식 (이름, 브랜드, 구매처/가게명, 가격, 원본 URL, 출처: naver|url|manual,
                       등록자, 등록일)
food_images       사진 (food_id, 이미지 URL 또는 Storage 경로, 순서) — 음식당 최대 5
tags              태그 (이름, 색상)
food_tags         음식-태그 (다대다)

taste_attributes  맛 항목 (이름, 아이콘, 순서, 활성 여부) — 관리자가 관리
ratings           평가 (food_id, user_id, 종합 만족도 1~5, 개인 메모, 수정일)  ※ (food_id, user_id) 유일
rating_scores     항목 점수 (rating_id, attribute_id, 0~5) — 매긴 항목만 행이 생김

comparisons       묶음 비교 (제목, 설명, 만든 사람)
comparison_items  묶음-음식 (comparison_id, food_id, 순서)

[뷰] food_stats   음식별 종합 평균, 항목별 평균, 평가 인원 수
```

**핵심 설계 포인트**

- **묶음 비교는 음식을 "참조"만 함** → 묶음에서 점수를 고치면 같은 `ratings` 행을 고치는 것이므로 개별 점수도 자동으로 바뀜 (명세 요구사항이 구조적으로 보장됨)
- **일부 항목만 평가**: 매긴 항목만 `rating_scores`에 저장 → 평균 계산 시 **안 매긴 사람은 그 항목 평균에서 제외**(0점 취급 안 함)
- 개인 메모는 RLS로 본인만 조회 가능

## 5. 화면 구성 (정보 구조)

```
로그인 ─ 초대 확인
│
├─ 홈 (음식 목록)
│   ├─ 검색 · 태그 필터 · 정렬(평균 높은순 / 최근 / 내가 안 먹어본 것)
│   └─ 카드: 대표 사진, 이름, 종합 평균 ★, 맛 프로필 미니 아이콘
│
├─ 음식 추가 ── [제품 검색] [URL 붙여넣기] [직접 입력] 3개 탭
│                └─ 저장 직후 "바로 평가하기"로 이어짐
│
├─ 음식 상세
│   ├─ 사진(최대 5) · 기본 정보 · 태그
│   ├─ 그룹 평균 맛 프로필(레이더) + 내 프로필 겹쳐 보기
│   ├─ 내 평가 (종합 ★ + 항목 슬라이더, 건너뛰기 가능 + 개인 메모)
│   └─ 그룹원별 평가 목록 (메모 제외)
│
├─ 묶음 비교
│   ├─ 목록 (예: "고기 만두 비교")
│   └─ 상세: 비교 표(셀에서 내 점수 수정) ↔ 레이더 겹쳐 보기 · 기존 음식 추가 / 새 음식 추가
│
├─ 내 평가 모아보기
├─ 태그 관리
├─ 설정: 글자 크기(4단계) · 테마(라이트/다크/시스템) · 데이터 내보내기(CSV·JSON)
├─ 업데이트 내역  ← 기본 포함
└─ 관리자: 멤버·초대 관리, 맛 항목 관리
```

- 모바일: 하단 탭바(홈 / 추가 / 비교 / 내 평가 / 설정), PC·태블릿: 좌측 사이드바
- 평가 입력은 **한 손 조작**을 우선: 항목별 큰 버튼(0~5) 또는 슬라이더, 미평가 상태가 기본

| --- | --- |
| 파스텔 | 배경·카드 채움에 파스텔(복숭아·민트·라벤더·버터 옐로). **글자에는 파스텔을 쓰지 않음**(대비 부족) |
| 귀여움 | 큰 둥근 모서리, 맛 항목별 아이콘(🌶️ 매운맛, 🍬 단맛, 🧂 짠맛 …), 빈 화면 일러스트 |
| 레트로 | 제목에 픽셀 느낌 한글 폰트(예: 갈무리 – OFL 무료), 굵은 외곽선 + 살짝 어긋난 그림자, 체크무늬·도트 배경 포인트 |

- **라이트/다크**: 색을 CSS 변수(토큰)로 정의하고 다크 모드에서는 채도를 낮춘 파스텔 + 짙은 남색 배경
- **접근성**
  - 글자 크기: 설정에서 4단계(작게/보통/크게/아주 크게) → 루트 글자 크기를 바꾸고 모든 크기를 `rem`으로 지정
  - 대비: 본문 글자 WCAG AA(4.5:1) 이상, 색만으로 정보 전달 금지(점수는 숫자 병기)
  - 키보드 조작·포커스 표시, 터치 영역 44px 이상
- 본문 폰트는 가독성 좋은 Pretendard, 픽셀 폰트는 제목·로고에만

## 7. 백업/내보내기 추천 → **수동 내보내기(CSV·JSON) + 주 1회 자동 백업**

- 이유: Supabase 무료 플랜에는 자동 백업이 없음. 데이터가 작아(수 MB) 백업 비용이 사실상 0
- **수동**: 설정 화면에서 "내 평가 CSV"(엑셀로 열기용), "전체 JSON"(관리자, 복원용) 다운로드
- **자동**: GitHub Actions가 매주 DB를 JSON으로 내보내 비공개 저장소에 커밋 → 백업 + 7일 일시정지 방지를 동시에 해결
- 사진은 용량 때문에 자동 백업에서 제외하고, 원하면 관리자가 수동으로 내려받기

## 9. 위험 요소와 대응

| 위험 | 대응 |
| --- | --- |
| 쇼핑몰 구조 변경·차단으로 URL 추출 실패 | URL 추출은 "되면 좋은" 보조 기능으로만 설계, 실패 시 직접 입력으로 매끄럽게 전환 |

| 쇼핑몰 이미지 링크 깨짐 | 기본 일러스트로 대체, "내 사진으로 바꾸기" 버튼 |
| Supabase 무료 플랜 일시정지·정책 변경 | 주간 자동 백업(접속 겸용), JSON 백업으로 다른 DB 이전 가능 |
| 맛 항목 기준이 사람마다 다름 | 항목별 짧은 기준 설명(예: 매운맛 3 = 신라면 정도) 표시 |
